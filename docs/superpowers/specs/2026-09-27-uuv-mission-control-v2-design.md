# PI 多 UUV 任务系统第二版修改方案

日期：2026-09-27。状态：讨论结论已整理，待书面方案确认；尚未实施或验收第二版。

本文是后续修改的设计基线，不是当前功能说明。与第一版 `tools/DESIGN.md` 不一致时，以本文的目标需求为准；当前已实现、已验证内容仍分别以源码和第一版验收记录为准。本轮只修改文档，不修改业务代码、不提交 commit。

## 1. 修改目标与边界

把目前“可调用算法的演示界面”改造成基于 PI 原生会话能力的长时、智能、人在环任务系统。重点不是增加更多聊天按钮，而是使观测、决策、授权、任务转换和实际执行一致。

已确认的产品要求：

- 二维游戏，8 艘己方 UUV 常驻任务场景，跟踪编队最多 3 艘，不模拟弱通信。
- Python 实现算法和运行逻辑，放在 `tools/`；继续接入 `ui/`，保留地图、场景编辑、回放和导出等已有功能。
- 保留 PI SDK，复用原生会话、工具事件、消息队列、压缩与持久化；浏览器呈现层按任务需要开发。
- 左侧“对话 / 数据”，右侧二维态势地图，下方任务运行台。
- 主动扫描产生目标接触；被动跟踪仅有带噪方位，由多艇融合估计位置和运动。
- 跟踪包含选艇、选择观测位置、航路规划、转场、获取有效观测和持续协同，不以“已分配”代替成功。
- 扫描子区域数等于当前可用于覆盖搜索的艇数；每区一艇、每艇一个主任务。区域连通、紧凑、可执行，保留覆盖进度并优先局部重划。
- 低能量艇驶离大任务区域后消失，同一仿真更新中补入满能量艇，维持 8 艘在场；不设置充电等待时间。
- Request / Assisted / Full 三种模式，计划内自主执行，超出授权范围再判断审批。
- 仿真独立持续运行，单个模型回合结束不结束任务。无安全可行控制时允许告警并保护性暂停。

不纳入本轮：实体装备控制、攻击、真实声学传播、弱通信、复杂水动力、训练强化学习、保证任意场景全局最优或永久不丢失目标。

## 2. 当前问题及修改方向

下表来自前期对当前源码的检查，不把第一版草案中的设想当作已实现能力。

| 当前情况 | 具体问题 | 第二版修改 |
| --- | --- | --- |
| PI worker 使用 SDK，但主要转发完成后的回复 | 看不到完整会话流，无法自然批注和运行中反馈 | 订阅原生事件，适配流式消息、工具与会话状态 |
| Skill 正文直接注入，关闭常规发现 | 没有利用按需加载机制 | 受信 Skill 目录与受限读取，采用 SDK 资源加载流程 |
| 默认搜索按 3+3+2 分组，矩形条带规划 | 不满足一个扫描艇负责一个动态子区域 | 工作量驱动的连通分区与一对一匹配 |
| 分配主要按距离和优先级 | 未充分考虑能力、能源、实际到达时间及覆盖损失 | 硬约束筛选后进行扫描匹配、跟踪团队联合评分 |
| 跟踪计划缺少实际入位路线，控制为距离带巡航 | 缺少“去哪里观测、如何到达、何时跟踪成立”的过程 | 观测位置候选、Dubins 转场、协同观测状态机 |
| 传感器提供带噪位置，未分主动/被动 | 无法演示纯方位融合 | 独立观测生成层和集中式方位 EKF |
| 覆盖统计未严格区分传感器模式与区域责任 | 跟踪也可能被算作扫描，区域进度不真实 | 全局覆盖账本、有效主动观测更新、按区域聚合 |
| 无逐艇能源与边界换艇生命周期 | 无法长期轮换与任务接续 | 航程模型、退出阈值、安全边界交替、新实体代次 |
| 既有测试验证单艇跟踪及有限长时场景 | 不能证明 2–3 艇有效协同、局部重划和换艇 | 新增针对第二版闭环的分层验收 |

不重写 PI 内核，不将实验性服务包作为必要依赖，也不把浏览器聊天伪装成可直接嵌入的 PI 原生 Web UI。本仓库已有终端 TUI、SDK/RPC 和静态导出能力；浏览器实时呈现由本项目负责。

## 3. 架构与职责

```text
浏览器：左侧对话/数据 | 右侧地图 | 下方任务运行台
                       |
Python 公共 API + 有序事件流 + 权限门 + 任务账本
       |                                  |
       | 决策事件/用户反馈                  | 候选计算/执行回执
       v                                  v
Node PI SDK 会话 + 受信 Skills + Extension Tools
                                          |
Python 算法：分区、分配、路径、跟踪候选、评估
                                          |
仿真 Runtime：固定步长、局部控制、能源、生命周期
       |
真值 -> 观测生成 -> 目标估计 -> BeliefState -> PI/规划/正常地图
```

Python 是仿真、权限、任务和计划的唯一写入者；Node 持有 PI 会话。沿用现有两进程结构，不新增一个重复的 API 网关。算法只计算候选，不直接改变艇位或任务。

PI 决定任务优先级、选择可执行候选、解释取舍；确定性算法负责数值计算；运行时负责每步执行和硬约束。LLM 不逐帧操舵，不创造能量、不修改传感真值、不自行批准。

任务常驻机制由固定步长运行时、事件触发决策、有限模型回合、检查点恢复组成。模型请求可以结束，任务仍继续；只有需要决策的事件才触发下一回合，而不是无限循环请求模型。

## 4. 数据与观测边界

### 4.1 三种状态

- `WorldState`：真实目标、己方、场景、随机数与物理状态，仅仿真内部持有。
- `ObservationBatch`：本周期实际获得的观测，含观测编号、时间、观察艇及代次、观察姿态、模式、噪声参数和测量值。
- `BeliefState`：可公开接触编号、估计位置/速度、协方差、最近有效观测时间、参与观察者、确认/退化/丢失状态。

己方位置、航向、航速、剩余航程与健康状态作为己方遥测共享。目标状态必须经过观测与估计，不能混在己方遥测中透传。

主动模式：带噪距离和方位，可派生带噪位置。被动模式：仅带噪方位，无目标真实距离、位置、速度或隐藏目标 ID。游戏用“主动雷达/被动雷达”作为两种传感模式名称，不宣称真实水下雷达物理。

建议首轮默认 8 艘均具备双模式载荷，但同一时刻只启用一种任务传感模式；能力字段保留，以便测试只能扫描或只能跟踪的平台。被动探测还要求目标在游戏配置中具有可探测信号，不能因为主动发现过就保证被动观测始终存在。

观测层根据模式、量程、遮挡、采样周期、噪声与漏检生成测量，不只是从完整 state 删除几个字段。每个传感周期只生成一次，查询 Tool 和刷新 UI 不产生新测量；所有消费者复用同一批带 ID 的记录。

真值仅供观测生成、独立评分和隔离的保护性暂停检查使用。正常状态 API、工具结果、模型上下文、时间线和回放均不得泄漏目标真值、未发现目标数量或场景内部标识。人工场景编辑与真值调试使用独立入口，不能仅靠前端隐藏图层隔离。

### 4.2 简化目标估计

采用二维恒速状态 `[x, y, vx, vy]` 的集中式 EKF。主动发现提供初始位置及不确定性；被动阶段用各艇带噪方位更新，角度残差归一化，按真实仿真时间差预测，处理重复、过期观测及异常残差。

观测不足时仅预测并增大不确定性；几何退化时不能凭空降低误差。估计器可使用转场中的真实观测，但不能据此提前宣布协同跟踪成立。首个验收场景使用一个目标，接口保留接触列表；复杂多目标交叉关联不属于首轮保证。

传感范围、噪声、丢失门限和协方差门限集中配置。初始可沿用现有场景尺度、4 m/s 航速和 60 m 最小转弯半径；新增噪声与成功门限在算法阶段通过固定种子场景确定并冻结，不将未经测试的数值冒充性能指标。

## 5. 覆盖账本、动态分区与任务指派

### 5.1 任务对象与不变量

扫描任务面向区域，跟踪任务面向移动接触，不能将跟踪限制在发现目标的原扫描区内。

`N_search` 统计健康、能力满足且能源足够、承担扫描或扫描转场责任的艇。跟踪转场、获取被动观测、有效跟踪、接替跟踪和低能量退出均不计入。不能只按“本帧是否开主动传感器”计算扫描艇数。

有效任务状态必须满足：

1. 在场己方实体数为 8；一个显示槽位仅有一个当前代次。
2. 活动扫描责任区数 `K = N_search`，区域与责任艇一对一。
3. 每艇最多一个主任务；跟踪组成员最多 3 艘。
4. 区域在可扫描水域内连通、不重叠，合并覆盖受管搜索域；无艇时域保留为无人负责的待扫描积压。
5. 分区编号、艇编号改变，不改变栅格已经获得的有效扫描成果。

覆盖账本按全局栅格保存最近有效主动扫描时间、累计有效扫描及重访需求，与艇/分区解绑。当前未扫描格可以不连通；连接走廊可以经过已扫描格。只有有效主动传感覆盖更新账本，被动跟踪或仅经过航点不算扫描。

“连通”使用栅格四邻接并考虑障碍；“紧凑”是优化目标，不承诺绝对最紧凑；“可执行”必须通过进入、转弯、扫描、离开及能源检查。障碍和明确不可扫描格不进覆盖率分母，不可达剩余水域另报，不能以静默剔除凑出 100%。

### 5.2 分区和一对一匹配方法

采用适合 8 艘规模的确定性启发式：依据艇位置及未完成工作量选种子，在自由栅格上进行有容量目标的连通区域生长，再通过不破坏连通性的边界格调整，降低工作量差异和区域周长。工作量包含剩余条带、转场、转弯及重访需求，不单纯均分面积。

先生成候选区域，再以可行 Dubins 路线的到达时间、预计扫描代价、剩余航程、区域优先级和换任务损失构造代价矩阵，复用 SciPy 一对一分配。不可行配对禁用；不能用很高的有限代价冒充硬约束。分区与匹配允许有限次数交替修正，预算耗尽明确返回失败。

艇退出扫描集合时，优先将其剩余责任区合并给相邻区域并调整边界；新艇加入时，优先拆分剩余工作量大的区域。未受影响区域尽量不变。局部无法修复时逐步扩大邻域，最后才尝试全局重划；仍不可行则报告原因，不强行给出碎片区域。

首轮场景要求自由任务水域连通且具备足够转弯空间。允许配置障碍，但若断开的水域分量数大于可用扫描艇数，严格的一艇一连通区无法覆盖全部分量，必须拒绝该运行配置或保护性暂停，不能悄悄放松用户约束。

区域内航线采用裁剪到自由水域的往复式条带，比较少量扫描方向；间距按有效主动覆盖宽度与重叠裕量计算，不继续使用与传感能力无关的固定间距。端点包含航向，转弯和条带连接复用 Dubins/前向绕障。窄区无法内部调头时，可在明确授权的邻接转场空间内机动，但不能因此改变区域责任归属或越过大任务区硬边界。覆盖进度按实际有效观测更新，遮挡、未到达和未扫描部分必须保留；不能用“航线走完”作为覆盖完成的充分条件。

### 5.3 状态提交与审批

候选计划不改变当前艇角色和分区。一个扫描艇拟转跟踪时，待审批期间仍执行旧扫描计划；批准后将角色变化、剩余覆盖交接、新分区和新航线作为同一事务，在 tick 边界切换。

建议启动任务时批准一份常驻策略，明确允许的本地补位范围、艇角色转换条件、搜索域、能源退出和边界换艇规则。范围内局部修复不重复审批，扩大授权域或改变目标优先级等超出范围的变化仍走当前模式。

常驻策略未授权的重划不能暗中执行。低能量退出不可延迟到耗尽：应提前触发决策；若到安全阈值仍缺少可执行且获授权的退出/交接方案，进入保护性暂停。暂停时标记分区失效并保留待扫描工作，不能展示一套假装满足 `K=N_search` 的活动分配。

所有正常运行快照满足上述不变量；故障快照明确标记 `allocation_blocked`，不声称方案仍有效。批准时对受影响任务/分区版本和艇代次重新校验，不用每帧变化让全部审批永久失效。

## 6. 多艇跟踪与任务切换

### 6.1 选择团队和观测位置

目标确认后，生成最多 3 艘的跟踪团队候选。优先尝试 2 艘实现方位融合，需要提升几何质量或接替韧性时比较 3 艘方案；仅 1 艘可用时显示单艇观测/预测退化，不能冒充多艇协同成功。不是把所有附近艇都抽走。

对预测目标位置周围的若干距离和方位生成观测位置及到达航向；结合预计到达时间重新预测目标，进行有限次迭代。位置是进入有利观测区的参考，不是要求恒速 UUV 悬停的固定点。

首先剔除能力、能量、边界、碰撞、路径和传感条件不满足的候选，再联合评分：

- 几何信息质量，例如方位信息矩阵的最小特征值或条件数；避免接近共线观测。
- 队伍到位时间和队内到达时间差，基于 Dubins 路径而非仅欧氏距离。
- 可保障跟踪时长、退出余量、扫描缺口、已执行任务的切换成本。

8 艘艇最多产生 28 个二艇组合和 56 个三艇组合，可以做有预算的候选枚举。观测位置匹配在给定队伍内求解；简单一对一分配不能代替整个耦合团队选择。LLM 可设置任务偏好并选择已校验候选，不得突破最少扫描能力、成员唯一性和能源硬约束。

保留必要扫描力量使用可配置约束；默认候选优先保留至少一艘可行扫描艇，但安全退出优先，不为满足比例占用已无安全续航的艇。当 `N_search=0` 时，明确显示零责任区与覆盖积压，不制造不存在的扫描资源。

### 6.2 执行状态机

```text
扫描 -> 跟踪候选/待审批 -> 跟踪转场 -> 获取有效方位
     -> 协同跟踪 -> 接替 / 观测退化 -> 丢失 -> 主动重搜索
任意任务 -> 低能量退出 -> 越界换艇 -> 扫描转场或新任务
```

转场完成由真实位置、航向和可观测条件判定，不由命令已接受判定。协同跟踪成立要求该团队成员的有效新鲜观测、足够几何质量和估计不确定性满足门限，并持续配置窗口；其他艇偶然看到目标不能替代团队执行验收。

建立跟踪后继续曲率受限机动，通过短时预测控制维持距离带与有利方位，不固定平移图标。原有 Dubins 核心及积分器继续复用，候选、控制与安全验证共用单位和约束。

短时漏检先退化预测；超过丢失门限后记录中断并申请主动重搜索，不把重搜索期间记作连续被动跟踪。模型与控制器使用 BeliefState，真值只用于独立评分/保护。

### 6.3 接替规则

区分接替已分配、已到达、已建立有效观测。原成员在能源允许时保持到交接成立；能源不足时必须退出并如实记录退化或丢失。

严格保持一个跟踪编队最多 3 艘：二艇团队可加入第三艇完成交接；三艇团队需要先评估能否由其中两艇临时维持，再释放一个席位并纳入接替艇。不能用“候补”名称让第四艘实际参与同一跟踪任务。无法兼顾上限与连续性时报告性能退化，不隐式突破上限。

跟踪、扫描补位和局部重划加入任务驻留时间、收益改善阈值与事件合并，防止频繁来回换艇。

## 7. 能源与边界即时轮换

采用演示级剩余航程模型，按实际航行距离扣减；传感器额外耗能可配置，但第一轮不引入复杂电池模型。UI 的“能源百分比”和“剩余里程”来自同一后端模型，不能各自估算。

退出阈值为当前可行退出路线消耗加安全储备，而不是剩余能量字面降到零。扫描可行性包含进入、预计剩余扫描、退出和储备；跟踪按可保障时段评估，并在储备触发前安排接替。

退出使用大任务区域的可通行边界出口和满足 Dubins 的路线，不能把障碍边缘当作补能边界。到出口后继续越过外边界，仿真器在同一更新事务中移除旧艇、插入满能量新艇。新艇在安全边界入口以向内航向出现，不在内部或目标附近生成。

显示槽位可仍叫 `UUV-1`，内部使用 `(slot_id, generation)` 区分。旧轨迹在退出点结束，新轨迹从入口开始；旧代次的计划、审批、控制命令和延迟观测不得作用于新艇。已形成的目标估计历史和全局覆盖成果保留。

换艇是明确的游戏生命周期事件，不是旧实体位置瞬移。任意公开提交后的仿真帧均有 8 艘；离场和入场的中间内部状态不公开。若没有安全入口，先保护性暂停，不能先删除导致只剩 7 艘，也不能生成重叠艇。

退出和补入可由启动时常驻策略授权；新艇领取任务仍受当前任务策略与权限门约束。正常补入后加入扫描候选集合，分区新增与任务接续原子生效；没有授权或可行任务时显示待指派，不虚报正在扫描。

典型计数：8 艘扫描时 8 区；2 艘转跟踪后 6 区；另 1 艘退出时 5 区；满能量替代艇接入扫描后恢复 6 区。在场总数始终为 8。

## 8. Tools、Skills 和权限门

### 8.1 Tool 契约

沿用现有九个入口，补足语义，新增一个独立分区计算入口。算法内部函数不必全部注册成 Agent Tool。

| Tool | 第二版职责 | 能否直接执行 |
| --- | --- | --- |
| `get_mission_state` | 己方遥测、BeliefState、覆盖摘要、任务与授权、代次 | 否 |
| `get_observations` | 分页读取已经生成的主/被动观测，按游标去重 | 否 |
| `partition_search_area`（新增） | 输入后端快照及可用艇集合，返回连通分区候选和工作量 | 否 |
| `compute_task_allocation` | 扫描一对一匹配或跟踪团队候选，包含硬约束诊断 | 否 |
| `plan_path` | 进入、转场、接替、退出的 Dubins 候选路线 | 否 |
| `plan_search` | 区域剩余扫描/重访/重搜索航线与有效覆盖预测 | 否 |
| `plan_tracking` | 观测位置、成员匹配、转场路线、获取条件、持续跟踪及接替策略 | 否 |
| `evaluate_plan` | 校验分区、能源、观测条件、成员、几何、版本与授权 | 否 |
| `submit_mission_plan` | 提交不可变组合计划，经代码权限门原子切换 | 是，唯一常规入口 |
| `get_action_status` | 区分计算、待批、转场、实际获取、执行、失效与完成 | 否 |

每个工具使用独立严格 schema，不继续以大量可选字段的通用对象混用参数。请求绑定 episode、任务快照、运行授权和算法版本；执行额外绑定计划版本、艇代次及幂等键。任务/分区关联变化使用同一组合计划。

返回值区分可行候选、预算耗尽、不可行、过期、取消、权限拒绝与服务故障；模型可读内容必须包含关键失败原因。几何和完整观测分页读取，不将长轨迹塞入全部模型消息。耗时计算使用有界后台作业和状态查询，取消后迟到结果不能提交。

人工批准、模式切换、恢复保护性暂停、停止仿真是人工控制 API，不注册成 PI 的自我提权工具。能源轮换为运行时规则，不要求模型每次调用“生成新艇”。

### 8.2 Skill 组织

继续使用 `.pi/skills/multi-uuv-recon-tracking/`，先维护一个主 Skill 与按需参考文件，不为了分层名称拆出相互重复的多套 Skill。

```text
SKILL.md                         观察、识别事件、选工具、评估、提交、核验
references/search.md             分区、责任艇、覆盖接续、重访
references/tracking.md           方位融合、观测几何、转场、接替、丢失
references/energy-turnover.md    退出阈值、边界换艇、代次
references/approval-policy.md   三种模式、授权边界与解释方式
references/tool-contracts.md    工具字段、单位、结果和失败处理
```

Skill 描述何时调用与如何理解结果；工具实现计算；权限由代码强制执行。只加载项目受信 Skill，使用 SDK 资源加载与受限文件读取，不开放任意 shell 或任意文件访问。需读取完整 Skill/参考资料时实际产生读取行为，不仅把 description 加进提示词就声称已经加载。

### 8.3 三种运行模式

Request：新计划或超出既有授权的变化等待人工批准；已经批准的常驻策略和计划内控制持续执行。

Assisted：常规且在授权范围内的变化自主执行，较高不确定性、较大覆盖损失、授权范围变化等请求批准。风险不是固定按工具名称给一个常数，更不是事故概率；硬约束不满足直接拒绝。

Full：无需逐项人工批准，但仍遵守任务授权域、人数、能源、几何、版本、部分观测和停止指令。三种模式均不能跳过安全检查。

审批显示具体受影响艇、分区变化、覆盖代价、观测预期、能源余量与回退。批准绑定不可变内容；批注和普通聊天不等于批准。切换模式不能复活已拒绝或旧代次计划。

## 9. PI 原生能力与长时运行

通过 `AgentSession.subscribe` 适配当前 SDK 实际事件类型，转发流式文本、消息结束、工具开始/更新/结束、压缩、重试和运行完成。不能将 `agent_end` 一概视作队列全部结束；按 SDK 的 settled 语义管理下一决策作业。替换会话后重新绑定订阅。

用户运行中反馈进入原生 `steer` 或 `followUp` 流程，并展示排队状态；steer 不被描述为立即强制中断工具。停止生成使用 abort，同时撤销该回合后续提交资格，但已经批准运行的任务继续。

任务账本、观测估计和控制状态不存放在模型记忆中。PI 压缩、断线或重启不会丢失这些状态。重连后由 Python 快照恢复任务语境，由 PI 会话恢复对话；会话分支不隐式回滚仿真世界。

事件按重要性合并，限制模型调用频率、单回合预算、排队长度与日志占用。周期检查是兜底，观测并非每帧进入提示词。模型不可用时显示离线/退化，继续已授权且可行的动作，不伪造回复或绕过审批执行新任务。

SQLite 检查点需新增覆盖账本、估计协方差、观测游标、能源、实体代次和任务转换状态。恢复不按墙钟补演离线航程。关键执行回执与状态同事务持久化；事件/回放设保留上限和分页，保持长期存储可控。

## 10. 界面与组件组织

```text
顶部：运行/暂停/停止 | 三种权限模式 | 仿真与 PI 状态
┌──────────────────────┬────────────────────────────────────┐
│ 左栏：对话 | 数据     │ 右侧：二维任务地图                  │
│ 原生消息流/工具/审批  │ 分区、覆盖、航线、方位、估计与误差域 │
│ 或 8 艘艇工作状态     │ 当前选择的任务与艇联动              │
├──────────────────────┴────────────────────────────────────┤
│ 下方任务运行台：任务时间线 | Agent 运行 | 任务指标          │
└───────────────────────────────────────────────────────────┘
```

对话采用 Codex 风格的紧凑工作界面：Markdown 流式输出、折叠工具结果、决策摘要、审批和输入队列。展示模型实际公开输出，不承诺暴露完整隐藏思维链，不制造假“思考过程”。Markdown 禁止未净化 HTML，工具及批注内容按不可信文本处理。

选中文本批注绑定原消息 ID、选中文字/定位范围和关联计划版本，提交后成为用户反馈。历史版本仍可批注，但旧批注不得自动修改新计划。保存引用，避免流式重绘导致批注指向变化。

数据页列出 8 个槽位：当前代次、主任务/阶段、剩余里程、能源、实时航速、位置、航向、传感模式、责任区域/目标及告警。明确区分航向与目标相对方位，单位由后端契约统一。

地图正常视图显示有效主动覆盖、区域归属、实际航迹、候选/已批准路线、被动方位线、目标估计与不确定域。跟踪转场与已建立跟踪使用不同状态。换艇不连接新旧轨迹；真值调试单独授权、明显标记。

下方三个页签：

- 任务时间线：发现、分配、待批、批准、转场、获取观测、跟踪建立、交接、丢失、重搜索、分区调整、退出与补入。
- Agent 运行：触发原因、真实工具调用、耗时、结果、错误/重试、压缩与队列状态。
- 任务指标：有效覆盖率、重访及时性、未扫描积压、有效协同跟踪时间、丢失时长、接替成功率及轮换次数。

按艇/接触/任务/级别筛选，事件点击联动地图与原消息；向上滚动暂停自动跟随，并显示新事件数量；合并高频重复事件。支持调整高度/折叠，不默认输出逐帧 JSON。任务事件用仿真时间，模型耗时用明确标注的墙钟时间。

区分停止生成、暂停仿真、取消任务和结束本局。回放只读；回放模式不能发实时批准。宽屏三分区，窄屏以页签/抽屉切换，不能靠缩小所有文字硬塞。保留场景编辑、AIS、重点区、参数和导出入口，但不混入正常目标真值流。

继续适配 `ui/用户手册与接口说明.md`，实施时同步更新新增帧字段、PI 消息事件、批注、艇代次、区域版本和权限契约；不另起一套与现有 API 无关的界面状态。公开事件至少关联 episode、序号、仿真时间、任务/计划版本、消息/工具调用 ID；重连使用快照加游标补齐，过期游标明确要求重载。

| A11 | PI 流式、steer/followUp、abort、压缩及重启 | UI 反映实际事件；取消生成不停止已授权任务；任务账本不依赖模型记忆 |
| A12 | 目标观测中断及重搜索 | 退化/丢失/重搜索分开计量；主动重搜索不算持续被动跟踪 |

| A14 | 连续运行与资源有界 | 至少 30 分钟墙钟及 4 小时加速任务场景，包含多艇搜索、跟踪和至少两次能源轮换，记录暂停/丢失/恢复及资源增长 |
| A15 | 桌面和移动浏览器 | 实际截图写入 `outputs/`，地图像素非空且运动，消息/数据/底栏无重叠，资产正常加载 |

运动学断言按同一实体代次检查，不把显式退出/新生事件当成旧艇瞬移。覆盖与跟踪分开统计；接替成功率分母为实际发起的接替，不是任意工具调用数。目标完全不可观测时不得要求算法凭空持续定位。

普通测试使用固定输入与假模型，不隐式消耗 API 额度；真实 LongCat 联调单列，并以实际工具回执为证。验收不承诺“一次 30 分钟测试证明永久运行”。模型断线场景与模型在线协同场景分别报告，不能沿用第一版单艇无目标 soak 代替第二版证据。

调参种子与验收种子分开，观测噪声、跟踪成立门限、能量预算和场景配置在正式验收前冻结并记入报告。验收报告同时给出原始指标和判定依据，不能在看到失败后放宽门限再声称原方案通过。

第一版仓库级 `npm run check` 有已记录的模型目录类型检查失败。后续验收必须重新运行并报告，不宣称当前全仓检查已通过；不能擅改无关测试或绕过检查提交。

## 13. 文献借鉴与简化说明

采用前期已讨论的文献作为方法背景，实施前核对所需公式与许可，不把“受启发”写成复现论文全部算法或性能。

- Chen 与 Qi，2023，*Research on the Cooperative Target State Estimation and Tracking Optimization Method of Multi-UUV*，[论文](https://www.mdpi.com/1424-8220/23/18/7865)。借鉴估计与协同观测机动的联动，不照搬分布式 IMM-EKF、融合与优化的全部复杂度。
- Hou 等，2021，*Adaptive Two-Step Bearing-Only Underwater Uncooperative Target Tracking with Uncertain Underwater Disturbances*，[论文](https://www.mdpi.com/1099-4300/23/7/907)。借鉴二维双观察者纯方位问题设置；本游戏采用普通恒速 EKF，不声称实现其自适应两步算法。
- Bishop 等，2010，*Optimality analysis of sensor-target localization geometries*，[作者机构页面](https://researchportalplus.anu.edu.au/en/publications/optimality-analysis-of-sensor-target-localization-geometries/)。借鉴信息矩阵评价观测几何，不将静态几何最优结论等同于带障碍、移动目标、有限转弯半径的完整最优航迹。
- Dubins、覆盖路径和跟随控制继续沿用 [第一版文献与许可记录](../../../tools/DESIGN.md#15-文献依据与工程边界)，复用已固定来源的实现；新的动态分区、联合评分和接替规则明确标为工程启发式。

## 14. 实现后的演示效果

用户启动一次任务并确定授权策略后，8 艘艇按动态分区主动扫描。地图显示真实覆盖进度；发现目标后，PI 给出抽调哪些艇及覆盖代价，工具生成观测位置和可行路线。审批后这些艇转场，其余艇局部接续扫描；到位并建立有效方位融合后，界面才显示协同跟踪。

运行中能看见估计误差域随观测几何变化、跟踪艇的入位和接替、低能量艇驶离边界及满能量艇补入。左侧对话可针对具体决策批注，数据页展示每艇状态，下方串起整个任务的因果事件。PI 回合结束、浏览器断开或模型短暂离线，都不会自动终止已授权任务。

系统不隐藏失败：几何不足显示退化，无观测显示丢失，缺少权限显示待批，无安全路径显示保护性暂停。这样演示的是可以核验的长时任务闭环，而不只是持续运动的图标。
