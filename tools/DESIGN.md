## 1. 目标、范围与责任

用户的工作主线是 PI 框架、界面组件组织以及 Tool 接口适配。本方案提供可落地的整体架构，并把配套 Python 算法、规则、测试及 PI 工具桥接集中放在 `tools/`，使用户以后可以独立替换算法。

已确认需求：

- 8 艘己方 UUV 可参与任务，任何执行编队最多 3 艘；不要求全部出动，也不固定为 3+3+2。
- 二维游戏演示，任务为目标 UUV 的搜索、确认、跟踪、丢失后重搜索；不包含攻击或武器控制。
- 不模拟水下通信延迟、丢包、带宽限制；各艇的有效观测集中共享。
- 算法以 Python 运行，PI 通过注册的 Tool 调用，Skill 描述使用知识与流程。
- 计算候选方案与执行方案分离；按任务计划授权，计划内自主执行，超出范围重新判断审批。
- Request、Assisted、Full 三种权限模式均由代码执行，Full 不取消硬约束。
- 仿真与控制不等待模型回复；UI 断开不结束任务，正常情况下没有预设任务结束时间。

为形成可实现方案，提出以下默认值，均不是用户已经确认的事实：

- 第一验收场景为 8 艘己方 UUV、1 艘目标 UUV，接口使用目标列表，但首版不宣称完成复杂多目标身份关联。
- 第一版采用静态圆形/多边形障碍、平面圆形传感范围和带噪声的位置观测，不做真实声学传播或水动力学。
- 任务结束一个搜索区域后进入重访或待命巡航，不结束全局服务。
- 极端无可行运动时允许保护性暂停仿真并提示原因。这是对“只有人停止”的一个显式例外，需用户确认；不能既承诺永不暂停，又承诺任意环境绝不碰撞。

## 3. 方案选择

| 路线 | 优点 | 不足 | 结论 |
| --- | --- | --- | --- |
| 单纯 Dubins 连接 + 固定任务脚本 | 最快验证运动与显示 | 无可靠绕障路径，不能充分展示重规划 | 作为第一步烟雾测试，不是最终方案 |
| Dubins + 仅前进的启发式绕障 + 小规模分配 + 滚动控制 | 可解释、无需训练、适合 8 艘规模 | 不保证全局最优，需要场景与参数回归测试 | 推荐 |
| 非线性 MPC / 学习策略 / 分布式协商 | 扩展空间大 | 求解、训练、调参与验证成本高；当前无弱通信需求 | 不作为首版必需项 |

不将“启发式实现”理解为每个 Tool 都必须包含优化算法。读取状态、提交计划和查询执行结果应是真实查询或状态机；计算工具才调用算法。

## 4. 模块与进程

```text
ui/                         浏览器显示和人工操作
  | HTTP + WebSocket
agent/                   Node 网关 + PI SDK 会话 + 任务调度器
  | 注册的类型化 Tool；私有 HTTP/事件通道
tools/uuv_game/              Python 应用
  |-- algorithms/           候选计划、分配、控制、评估
  |-- runtime/              仿真时钟、观测、接触管理、持久状态
  |-- permissions/          权限策略、审批、提交校验
  |-- adapters/             仿真替换接口、UI 帧转换
  `-- api/                  内部类型化接口
```

两套后端进程足够，不为每个算法部署一个服务。Python 是仿真状态、计划、审批和执行结果的唯一写入者；Node 是 PI 会话和调度队列的所有者。Python 规划工作使用不可变快照，在工作进程执行，不阻塞仿真时钟。

Python 演示运行时是一个可替换的最小仿真适配器，用于没有外部仿真服务时端到端验收；若用户提供权威仿真程序，则接入其接口，不重复维护两个仿真世界。

PI 只获得裁剪后的任务观测，不接收 UI 的调试真值帧。关闭不必要的 bash、写文件、任意网络等工具；只启用任务工具和读取受信 Skill 的受限能力。仅隐藏工具不等于操作系统安全隔离，真正部署时需进程身份/凭证/网络边界配合。

## 6. 坐标、时间与 Dubins 运动学

### 6.1 内部统一单位

- 平面坐标米、时间秒、航向弧度；`x` 向东、`y` 向北、航向逆时针为正。
- 状态至少包含 `(x_m, y_m, heading_rad, speed_mps)`，不能只有位置。
- 任务时间由 `sim_time_s` 决定，HTTP 超时和模型超时使用墙钟时间。
- 20 倍加速意味着每秒运行更多固定步长，不把单步长度放大 20 倍。

运动模型：

```text
dx/dt = v cos(heading)
dy/dt = v sin(heading)
dheading/dt = v * curvature
v > 0, abs(curvature) <= 1 / min_turn_radius_m
```

首版活动航行使用配置的固定正速度；不倒车、不横移、不原地旋转。停车/靠泊属于非活动状态，不假装是连续 Dubins 航行。活动待命采用经碰撞检查的盘旋路径，不把速度随意置零。

使用恒定控制区间的直线/圆弧精确积分；航向做角度归一化。速度或曲率参数变化只在控制边界生效，位置与航向必须连续。Dubins 允许曲率切换，不保证曲率导数连续，不等价于真实 UUV 动力学模型。[R1, R2]

### 6.3 UI 坐标适配

沿用外部 `task_area.width_km / height_km / cell_size_km`、`uavs[].position` 和列优先 `matrix[col][row]`。现有渲染路径存在中心偏移，实施前以 CanvasMap 实际调用链建立往返测试；目标转换约定为中心索引坐标：`col=x/cell_size-0.5`，`row=(height-y)/cell_size-0.5`。bbox 使用网格边界而不是中心索引，必须单独转换。不得把米直接写入 `position`。

## 7. 工具契约

### 7.1 通用约定

所有工具参数使用固定 schema。请求包含 `request_id`、`episode_id`，计算工具还绑定 `snapshot_id`、`mission_revision`、`algorithm_id` 与受限 `options`。快照必须来自后端，PI 不能提交伪造的实时艇位或策略版本作为权威状态。

计算返回：`result_id`、`status`、输入版本、实际算法及版本、种子、指标、限制和诊断。`status` 至少区分 `succeeded`、`infeasible`、`timed_out`、`cancelled`；另以 `solution_quality` 区分无解、可行但未证最优、已证最优。超时仍可能带有已校验的可行候选，但不能返回已证最优。基础设施异常与合法的“无可行解”分开。

大轨迹存在服务端，以 ID 引用；PI 获得摘要和必要指标，UI 按需读取几何。TypeScript 工具的 `content` 提供模型可读摘要，`details` 提供结构化数据，不能假设模型会自动看见只放在 `details` 内的重要结论。

耗时任务快速返回 `job_id`，通过 `get_action_status` 或完成事件获取结果。UI 现有默认 HTTP 超时为 10 秒，不能让长任务在请求里无限等待。取消模型生成与取消 Python 作业分别记录，不能把连接断开当作远端工作已取消。

### 7.2 工具清单

| Tool | 输入重点 | 核心实现 | 副作用 |
| --- | --- | --- | --- |
| `get_mission_state` | episode、可选编队过滤 | 权威观测视图、8 艘状态、编队、模式、授权、计划摘要 | 无 |
| `get_observations` | 时间/序号游标、contact 过滤、limit | 有界观测查询，不返回目标真值 | 无 |
| `compute_task_allocation` | snapshot、候选任务、偏好 | 1-3 艘候选编队评分 + 小规模组合优化 | 只保存候选结果 |
| `plan_path` | snapshot、uuv、目标 pose、约束 | Dubins 六族连接，碰撞后调用前向绕障 | 只保存候选轨迹 |
| `plan_search` | snapshot、成员、区域、search/reacquire | 条带覆盖、转弯连接、时间分离、可达性检查 | 只保存候选计划 |
| `plan_tracking` | snapshot、contact、成员、参数范围 | 目标预测、相对槽位、角色匹配、滚动跟踪策略 | 只保存候选策略 |
| `evaluate_plan` | 不可变候选计划 ID | 统一约束、碰撞和风险检查 | 保存评估，不授予权限 |

相比之前 8 个工具，本方案增加独立 `plan_path`，用于 Dubins 验证和算法实验；搜索/跟踪工具内部也复用它。`replan_path` 不单独注册，使用同一规划接口和最新快照。

人工暂停、恢复、停止、模式切换、批准/拒绝是控制 API，不是让 PI 自己调用的提权工具。若兼容既有 `sendCommand` 接口，只接受白名单结构化命令，并进入同一个网关。

## 8. 算法与启发式规则

### 8.1 点到点规划

1. 输入完整起终 pose 与 `min_turn_radius_m`。
2. 复用 Dubins 核心生成 LSL、RSR、LSR、RSL、RLR、LRL 各可行候选；按长度和净空评分。[R1, R2, I1]
3. 检查完整圆弧/直线，不仅检查端点。剔除越界及进入膨胀障碍的候选。
4. 无直接有效连接时，采用仅前进的 Hybrid A* 思路，保留连续 pose，用离散位置/航向作为搜索索引；动作只有前向直线与有限曲率圆弧，终点连接用 Dubins。[R3]
5. 优先改造许可允许的现有实现；明确删除本任务不允许的倒车动作、倒车代价分支和 Reeds-Shepp 终点连接，不把原版汽车规划器原样套用。[I1]
6. 重复 pose 返回零长度路径，接近零长度、角度跨越正负 pi、过小转弯空间等均有专门测试。
7. 设定最大扩展数和求解墙钟上限；超限返回 `timed_out`，不能谎报数学不可达。失败不回退成直线穿障或瞬间转向。

点到点路径只是几何计算结果。可提交执行的计划必须同时包含终点后的连续航线或已校验待命盘旋，不能在最后一个航点直接停车；零长度候选不能单独作为活动艇的持续控制计划。

这里的 A* 绕障是有界计算预算的启发式版本，不声称全局最优或对所有连续场景完备。路径平滑只允许使用重新校验的曲率受限连接，不能任意样条平滑后假定仍满足转弯半径。

### 8.2 编队与任务分配

最多 8 艘时，1-3 艘候选子集总数为 92，规模允许显式比较候选队伍。步骤：

1. 保留仍有效、受授权保护的既有任务；只为允许调整的艇生成候选。
2. 对每项候选任务生成满足人数、可用性和能力要求的编队。
3. 评分包含预计到达时间、搜索收益/目标优先级、重组代价、对已有跟踪连续性的影响。时间成本优先使用 Dubins 长度，不只使用直线距离。
4. 用二元变量选择“任务-编队”组合，约束每艘艇最多被选一次、每项任务最多一个编队，允许未分配艇保留原任务或待命。使用 SciPy `milp`，显式设置整数性和 0/1 上下界，不自行实现通用 MILP。[I3]
5. 有求解时间限制；有可行 incumbent 时明确返回 `feasible_not_proven_optimal`。没有可行解时返回失败或经过同样校验的显式启发式候选，不静默声称最优。
6. 加入重组冷却和收益改善阈值，防止轻微状态变化导致反复换队。

跟踪位置槽位的一对一匹配使用 `linear_sum_assignment`。它解决的是给定代价矩阵的匹配，不等于完整编队协同问题；SciPy 实现为修改后的 Jonker-Volgenant，不标注为原版 Hungarian。[R6, I2]

### 8.3 搜索与重搜索

以 Boustrophedon 往复式覆盖思想为基础。[R4]

- 首版场景以矩形搜索区和稀疏障碍为主；比较水平/垂直扫描方向的总航程与转弯代价。
- 条带间距不超过有效传感覆盖宽度，并留重叠裕量；最多三艘分担不同条带或子区域。
- 条带端点包含航向，调头由 Dubins 或前向绕障完成。窄条带需要更大调头区或跳行顺序，不能强行半径更小地掉头。
- 允许在任务授权的转场走廊内转弯；不得因为转弯需要而悄悄越过硬边界。
- 信息新鲜度使用后端扫描时刻和半衰期更新。后续选择低覆盖/低新鲜度且价值高的区域持续重访。
- 目标丢失后，按最后估计位置、速度与不确定范围生成有界重搜索区域，仍调用相同覆盖内核；不读取真值寻找目标。
- 输出预计覆盖率与遗漏区域，不把工程简化版本称为原文完备覆盖算法。动态目标被发现也不是静态区域覆盖率高就能保证。

### 8.4 观测与目标估计

运行时按固定仿真周期产生带噪位置观测，条件为距离在传感范围内且未被配置的遮挡阻断。无弱通信意味着立即共享有效观测，不意味着全部目标可见。

首版使用已验证数值组件实现二维恒速状态估计，状态为 `(x,y,vx,vy)`，按真实观测间隔预测和更新；必要时用简单残差门限拒绝明显异常。观测 ID 去重，不能把 UI 重发同一条观测算作新的确认依据。

接触状态为 `tentative -> confirmed -> tracking -> lost -> reacquiring`。初始确认可采用“最近 5 次传感周期至少 3 次有效观测”的演示规则；丢失依据配置的无观测时长与估计误差范围。规则参数写入配置，不作为真实传感器性能结论。

目标真值由仿真器保存，只供传感器生成、评分和显式调试视图。PI、算法决策和正常任务视图使用估计态；不得从 `scenario_vessels` 或调试帧绕回真值。

### 8.5 跟踪与交接

`plan_tracking` 返回可执行策略，而不是永远追逐一个静止航点。

1. 根据估计速度短时预测目标位置，生成满足期望距离和观测范围的候选相对位置。
2. 对 1-3 艘选取不同位置槽位，用分配求解器减少重复占位与大幅交叉。
3. 每艘使用曲率受限路线接近槽位，局部控制持续更新；所有己方控制只使用估计态。
4. 移动参考点必须受位移/航向变化限制；目标急转时允许临时跟踪误差并重规划，不允许追踪艇瞬移或原地转向。
5. 若目标比跟踪艇快、边界限制太强或观测中断，明确报告跟踪不可维持，不承诺任意目标永不丢失。
6. 交接时先让接替艇获取连续观测，再释放原跟踪任务；采用新的计划版本，不能只以命令发送成功作为交接完成。

跟踪槽位与重规划阈值是本演示的工程启发式，不声称来自某篇论文的完整最优协同策略。

恒速己方比目标快时，不能永久保持固定相对槽位。首版把槽位作为接近引导，持续跟踪改为目标估计位置附近的距离带巡航：建议距离带为 120-280 m，由短时曲率采样选择沿带机动的可行轨迹，不要求固定相对位置或严格画圆。代价优先保持观测与净空，再优化距离误差；多艇分配不同参考方位以减少交叉。移动参考轨迹仍逐段检查真实速度、曲率和碰撞，不把目标平移简单叠加到圆轨迹上并假定运动学成立。上述距离带是软目标，无法维持时报告退化或丢失，不违反硬约束强行追随。测试包含目标静止、慢速直行和急转三种情形。

### 8.6 路径跟随、编队与避碰

参考 Pure Pursuit 的几何前视思想，依据参考路径前方点生成曲率；在下发前约束 `abs(curvature)<=1/Rmin`。[R5] 当前执行始终通过运动学积分推进，而不是直接给位置赋值。

编队不是把三个图标固定平移：每艘有独立的 pose、曲率约束、碰撞包络和控制量。任务编队指成员关系；几何队形是可松弛参考，避碰优先于队形整齐。

当参考控制预测产生冲突时，枚举少量可行前向曲率，滚动预测短时轨迹，按路径误差、目标观测质量、净空和控制变化选取候选。这借鉴速度空间/短时前向评估思想，不是原版 DWA 的完整复现，因为首版恒速模型不包含原文的制动可达性条件。[R7]

多艇使用确定性的优先顺序、短时预测轨迹预约和重新校验，减少双方同时避让振荡。碰撞检查覆盖两个采样点之间的扫掠区域；圆弧离散时计入弦高误差和艇体膨胀裕量，不能只检查离散点。

若所有控制都不可行，先尝试已校验的待命盘旋/回退计划；没有可行回退时进入保护性暂停并记录 `safety_infeasible`，不编造安全保证，也不把 UUV 原地旋转当作解决办法。

己方间安全检查使用共享的己方状态。相对目标只使用估计位置和不确定性裕量，不能声称它等价于真实距离硬保证。仿真器可以用真值做独立的碰撞评分和保护性暂停检查，但该检查仅产生事件/冻结仿真，不向规划器提供真值或以真值计算避让命令。若选择不启用保护性暂停，则真实碰撞应记录为游戏失败事件，不能宣称算法保证了无碰撞。

## 9. 权限与计划状态机

硬性约束优先于风险评分：人数、成员唯一性、曲率、障碍、边界、过期版本等不能被低风险总分抵消。

| 模式 | 已授权范围内且通过检查 | 新增/扩大任务范围 | 硬约束不满足 |
| --- | --- | --- | --- |
| Request | 按已有批准计划执行 | 等人批准 | 拒绝 |
| Assisted | 规则允许则自动执行 | 按受控委托范围及风险规则请求批准；不可自动扩大硬边界 | 拒绝 |
| Full | 在预先设定的任务权限内自主执行 | 可调整权限内的计划；超出硬授权拒绝，不无限等人 | 拒绝 |

```text
draft -> evaluated -> pending_approval / approved / rejected
approved -> queued -> active -> completed / superseded / failed / cancelled
pending_approval -> approved / rejected / expired / cancelled
```

审批绑定计划不可变内容、编队、任务范围、策略版本和有效期。实时运动的每一帧变化不自动导致计划全部作废；用任务/地图/编队等离散版本及可接受位置偏差判断，再检查当前态势。参数被修改、地图改变或偏差过大时重新规划/审批。

完整计划先校验后在一个仿真 tick 边界原子切换，避免半数艇加入新队、半数仍执行旧队任务。每个 `command_id` 持久幂等，同 ID 不同内容直接冲突。已接受不等于已完成。

等待审批不停止仿真，也不阻塞 PI 持续观察：提交工具快速返回 `pending_approval`，后续批准事件再触发执行和通知。批准接口由人类会话身份调用，PI 无权调用批准接口或修改权限模式。

每份航行计划的授权同时覆盖终点待命和故障回退，记录允许区域、控制范围、有效期及触发条件。局部跟随和避碰只能在该范围内调整；越出范围必须走新计划网关。旧任务结束、失效或模型不可用时，只能转入仍有效且当前可行的已授权回退；没有这种回退时进入明确的保护性暂停，不能临时生成未经批准的新任务。首次启动且尚无航行授权的艇保持非活动初始状态，仿真时钟和目标运动仍可继续。

## 10. PI 调度与 Skill

### 10.1 任务调度

- 同一任务同时最多一个 PI 决策回合；传感状态采用最新快照覆盖，不把每帧塞进对话。
- 触发事件：人工消息、目标确认/丢失、计划失效、交接完成、关键执行失败、周期复查。
- 同类事件合并，保留关键状态跃迁与事件 ID；设置墙钟最小调用间隔和单次工具/模型预算。
- 预算限制的是单个回合，不是全局任务寿命。回合结束后 Runtime 继续监测。
- 模型超时只使 Agent 进入 degraded；已授权的控制继续，未授权新任务不能被“故障回退”绕过审批。
- 支持明确标识的 heuristic 演示模式，不调用模型也能验证算法与 UI；它和 PI 模式共用权限网关，UI 不得把规则输出伪装成 LLM 回复。
- 用户停止高优先级处理，不等待模型回合；停止后禁止后台恢复继续下发旧命令。恢复需要显式指令和当前状态校验。

### 10.2 Skill 内容

主 Skill `multi-uuv-recon-tracking` 明确以下流程：

1. 获取任务观测快照和当前授权，识别触发事件。
2. 有效旧计划优先延续；无实质变化时不反复计算。
3. 搜索阶段调用分配和搜索工具；新接触先核对观测，而非直接声明目标确认。
4. 目标确认后生成跟踪候选；丢失后生成重搜索候选。
5. 评估候选并提交计划，解释网关结果，不自行宣称批准。
6. 查询执行回执，等待实际交接/执行事件，汇总简短决策理由。

参考资料记录各工具输入语义、失败处理、参数范围、编队上限、重规划触发条件和审批规则说明。需要使用时显式读取，不假定全部自动加载。关键权限规则只由后端配置提供权威值，文档不得成为第二份可漂移的规则源。

不把选择算法与优化参数无限放给模型：算法 ID 为注册白名单，所有参数有界。实验时由场景配置锁定算法，避免一次对比实验中 PI 自行更换基线。

## 11. UI 与 API 适配设计

### 11.1 组件组织

- `App`：只保留布局和选择态，任务数据进入统一 hook/store。
- `CanvasMap`：复用地图、轨迹、覆盖场；增加编队标识、候选路线与估计不确定区域，真值仅在调试层显示。
- `RightSidebar`：组合 AgentChat、ApprovalQueue、AutonomyControl、TeamStatus；原接触/重点区/场景信息保留为可切换视图，不无限堆长侧栏。
- `BottomDrawer`：默认提供可展开时间线，展示观测事件、工具参数摘要、算法结果、审批和执行；不声称展示模型隐藏推理。
- `PlaybackBar`：只读回放，不向实时仿真发送重规划或批准操作。
- 模型名称来自后端，不保留写死的 LongCat 默认标签作为真实运行状态。

新增组件是组织逻辑调整，不重做现有视觉设计。工具核心与配置仍放 `tools/`，前端只负责提交和显示。

### 11.3 实时与恢复

遥测允许丢弃中间快照以保持流畅；审批、任务状态跃迁和工具结束事件不允许靠帧合并丢失。事件有递增序号，重连先获取完整状态再按游标补齐，重复事件按 ID 去重。

新 episode 必须清除旧帧合并缓存、信息场、事件列表和当前选择，不能把上一局矩阵混进新局。信息场实时模式以后端版本为准，断线保留最后一帧并明确标记 stale，不在浏览器继续推演假装实时。

## 12. 持久化与长时运行

- Python 使用 SQLite 保存场景配置、任务、计划版本、审批、幂等命令、事件和周期检查点；PI 使用已有 SessionManager 保存会话。
- 仿真状态只有一个写入线程/循环，重规划工作进程只能提交候选，不直接修改状态。
- 检查点包含真值、观测估计、信息场、随机数状态、活动控制器和任务版本；恢复后与执行账本核对。
- 状态不明的命令先查询回执，不能盲目重发。恢复不把进程离线期间按墙钟补演成 UUV 已移动。
- 轨迹、日志、事件、回放文件设置分块与保留上限；长时间运行不等于永远在内存保存全部历史。
- UI 保留有限窗口，历史按页查询；Agent 上下文只含当前任务摘要、近期变化与必要历史。
- 明确日志无密钥，API token 和模型凭证不进入 UI、工具结果或回放文件。

## 14. 验收测试

### 14.1 数学与算法

- Dubins 六种族、重复起终 pose、跨 pi 航向、最小半径边界；路径端点与航向误差满足测试容差。
- 每段路径/每次积分无负速度、无瞬移、无原地转向，曲率不超过上限。
- 窄障碍位于采样点之间时仍能被扫掠检测发现；障碍、地图边界和动态艇间冲突均有反例。
- 不可行与超时明确区分，不生成伪成功路线。
- 每队最多 3 艘、所有成员来自 8 艘、不重复占用；任务分配不因默认值强制 8 艘全出动。
- 搜索真实扫描面积增长，调头处满足曲率；小于可转弯尺度的区域正确报告限制。
- 跟踪曲线连续；目标急转、消失、重新出现时估计和状态机有合理转移。
- 同 seed、同输入快照、同算法版本给出可复现结果；性能依赖墙钟的超时结果单独记录。

### 14.2 权限与恢复

- 未批准、过期批准、被修改计划、旧 episode、旧策略版本均不能执行。
- 模式切换重新评估未执行计划；切换 Full 不自动追认旧的被拒绝动作。
- 相同 command_id 重试只执行一次；冲突内容被拒绝。
- 审批延迟期间仿真继续；批准时重新校验当前情况，但不会因每帧版本递增而永远无法执行。
- 进程重启后不丢失待审批项，不重复应用已经提交的计划。
- 人类暂停/停止不排队等模型；保护性暂停必须有独立事件和原因。

### 14.3 UI 与演示场景

- 场景 S1：8 艘分组搜索，发现 1 个目标，一队转跟踪，其他艇继续搜索或待命。
- 场景 S2：目标短时离开传感范围，显示丢失与不确定区域，重搜索后恢复跟踪。
- 场景 S3：人工收紧授权范围，展示待审批、拒绝、修改计划和批准全过程。
- 场景 S4：障碍挡路，曲率受限重规划，没有直角折返或穿越障碍。
- 场景 S5：断开 UI、模拟模型不可用后恢复，仿真时钟和有效任务连续。
- 桌面与窄屏浏览器检查地图/聊天/底部时间线，使用截图和 Canvas 像素检查确认非空、实体确实移动、无组件重叠。
- 连续运行至少 30 分钟墙钟和 4 小时加速仿真作为初始 soak test，记录队列、内存、事件和磁盘增长，不把这些短测试等同于“永久不故障”。

## 16. 确认后开始实施的边界

确认这份方案后，先实现 A-C 阶段中的 `tools/` 核心及测试，再接 PI 与现有 UI。最需要确认的产品例外是：当严格前向运动与无碰撞条件无法同时满足时，是否接受明确告警的保护性暂停。若要求绝不自动暂停，就必须另行定义失败/碰撞的游戏规则，不能隐式放弃运动学或安全约束。
