# PI 多 UUV 任务演示

`ui/` 接入 Python 仿真和 PI SDK。对话、地图、审批和任务运行台共享后端状态。场景保持 8 艘己方 UUV 和 1 个敌方目标，每个跟踪编队最多 3 艘，搜索采用一艇一区；不模拟弱通信。

仿真与算法调参集中在 [`configs/uuv_game.json`](../configs/uuv_game.json)：`simulation` 为地图、声呐、速度、续航与覆盖窗口；`algorithms` 分别列出场景、区域匹配、Dubins/Hybrid A*、CBS、覆盖巡航、目标估计、跟踪控制、能源轮换和任务调度的行为阈值。修改后需重启 Python 服务才会重新加载；修改已存档局的初始场景不改变该局历史状态。栅格边长、地图尺寸及舰队数量属于关联参数，不能仅修改一项就认为既有 8 艇/40×40 场景测试仍适用。

本文描述当前实现，不是验收通过声明。本轮结果与边界见 [ACCEPTANCE-v3.md](ACCEPTANCE-v3.md)，第二版历史结果及失败记录见 [ACCEPTANCE-v2.md](ACCEPTANCE-v2.md)。短场景、故障注入测试或真实模型成功调用工具不能替代长时验收。

## 启动

建议 Python 3.13、Node 22.22 或兼容版本。MP4 导出及后台界面录制另外需要系统 `ffmpeg`；后台录制还需要 Playwright 的 Chromium 浏览器。

```sh
npm ci --ignore-scripts
npm run hydrate:model-data
npm --prefix ui ci --ignore-scripts
python -m venv tools/.venv
tools/.venv/bin/pip install -r tools/requirements.txt
tools/.venv/bin/python -m playwright install chromium
```

通过环境变量提供 `LONGCAT_API_KEY`，或使用本机忽略文件 `outputs/runtime/credentials.env`。文件内容是 `LONGCAT_API_KEY=实际密钥`，目录权限应为 700、文件权限为 600。不要放进 `ui/`、Vite 环境变量、命令行参数或版本库。

```sh
./run.sh
./run.sh --status
./run.sh --stop
```

`run.sh` 可从其他工作目录调用；优先使用 `tools/.venv/bin/python`，否则使用 `python3`。启动器默认选择后端 8765、前端 5173；端口占用时自动选择其他端口，真实地址记录在 `outputs/runtime/services.json`。`./run.sh --no-model` 可运行仿真算法与界面而不请求模型，界面会显示 PI 离线，不伪造模型回复。`--foreground` 用于终端前台管理。已有后台进程时再次启动只报告状态；停止会中断当前任务。

## 界面与操作

- 左侧“对话 / 数据”：PI 公开流式回复、折叠工具结果、批注和输入队列，或 8 个槽位的代次、任务阶段、能源、剩余航程及遥测。审批和任务规划保留独立入口。
- 右侧二维地图：责任区域、有效主动覆盖、实际航迹、规划路径、被动方位线、接触估计与不确定性。跟踪转场不显示为已建立协同跟踪。
- 顶部：仿真开始、暂停、停止、重置，以及请求批准、辅助批准、完全自主三种模式。停止后需重置开启新任务。
- 顶部录制按钮：开始录制完整的实时桌面界面，再次点击停止；转码完成后在 `outputs/mission-*.mp4` 查看文件。关掉操作员标签页不会停止录制，重新打开页面仍能看到录制状态并停止。后端重启/崩溃不保证视频完整，转码失败时原始 WebM 会留在 `outputs/`；长时录制需预留原始和成品视频的磁盘空间。回放模式已有单独的地图导出功能。
- 下方任务运行台：“时间线 / Agent 运行 / 任务指标”，保留区域、参数和 AIS 入口。工具、重试、压缩和队列事件来自 PI 会话，不展示隐藏推理。

单目标版本关闭新增船舶、AIS 广播和场景真值入口；旧场景修改接口明确返回 409。敌我双方仅接收各自观测，地图只显示我方已发现目标的估计和失联预测，不显示未发现目标的真值。

地图保留原海域底图，责任区、责任艇和航线使用稳定关联色。己方使用 `ui/public/assets/uuv.png`；目标估计使用从 `submarine.png` 生成的透明底 `submarine-transparent.png`，不改写原图。重新生成可运行 `python tools/prepare_submarine_asset.py`。艇首朝向按世界航向或目标估计速度转换，未知目标速度时不伪造朝向。

第一次演示可选择“请求”，发送“为8艘UUV准备一艇一区的舰队搜索计划，包含能源退出、边界补入和局部覆盖接续的常驻授权，评估后提交，等待批准”。确认候选、批准并开始仿真后，再观察真实搜索和接触事件。常驻授权包含在计划审批中，不是模型自行批准。

运行中的消息可选择原生 `steer` 或 `followUp`；前者在当前工具执行后的会话边界反馈，后者排在后续回合，不等于立即中断工具。批注保存原消息引用，但不批准或直接修改计划。“停止生成”撤销该模型回合的后续执行资格，不停止已授权仿真。回放只读。

等待模型或审批不会暂停已授权任务。缺少授权的艇处于非活动状态。保护性暂停、人工暂停与 PI 取消是不同操作；保护性暂停只允许人手动恢复。

## 实际架构

```text
ui/                 HTTP / WebSocket
  |
adapter/api.py      公共 API、内部工具接口、串行决策队列
  |                     ^
runtime.py           agent/worker.ts
  |                  PI SDK + LongCat + Extension + 受信 Skill
  |
observations.py     主动距离/方位、被动纯方位 EKF
sensing.py          单周期采样、观测游标与覆盖账本
algorithms/         分区、路径、团队候选与联合曲率选择
lifecycle.py        能源退出、边界补入和区域修复
handover.py         有界跟踪接替与实际观测确认
  |
SQLite              检查点、回放、幂等回执、历史计划
```

Python 是状态权威，Node 只负责 PI 决策回合。模型不逐帧驱动运动。后台进程由启动器监护，浏览器关闭不终止仿真；程序崩溃后从检查点恢复，不补演离线期间的运动。检查点周期为 1 秒，因此进程崩溃可能损失最后不到一个周期的遥测，已提交的计划和回执则使用同一事务。

敌方由独立 `agent/adversary.ts` 原生 PI 会话控制，只有 `get_adversary_observation` 和 `set_evasion_parameters` 两个工具，使用独立令牌、运行租约和私有历史。敌方探测半径 700 m，我方 350 m；两者都存在噪声与遮挡。敌方 LLM 只能设置 0..3 m/s 速度、-1..1 转向偏好和 1..60 仿真秒有效期；80 m 最小转弯半径及安全弧线检查由 Python 控制器执行。参数失效后回退到 2.5 m/s、零偏好与近距离避让，不等待模型。每轮最多 3 次模型请求、4 次工具调用、60 秒墙钟时间，保留最近 100 份已完成的私有会话文件。共享界面仅暴露敌方服务状态，不暴露其观测、决策文本或真值。

在线演示默认采用2倍仿真时钟，艇速仍为4 m/s。真实模型的多轮工具调用需要墙钟时间；过高倍率会使候选航线在提交前起点失效。当前200 m起点新鲜度检查没有放宽，2倍时钟为直线移动提供约25秒预算，仍不保证任意模型延迟都能提交成功。离线验收直接推进固定步长，独立控制加速倍率。

计算使用后台线程及只读快照，在返回时再次检查 episode。线程不是实时隔离保障；规划受节点预算约束。浏览器普通读取默认超时 10 秒，任务修改请求为 120 秒，worker 内部请求为 30 秒。极端请求可能超时，需要查询实际状态，不能盲目重复提交；本版没有远端可取消计算进程。

## 十个任务 Tool

| Tool | 职责 | 算法/状态来源 |
| --- | --- | --- |
| `get_mission_state` | 读取当前任务、己方状态、观测接触、授权 | 后端快照，不含目标真值 |
| `get_observations` | 按游标分页读取已生成观测 | 主动带噪距离/方位，被动仅带噪方位；查询不重新采样 |
| `partition_search_area` | 计算一艇一区的连通责任区候选 | 工作量加权二分、局部合并/拆分及可行匹配 |
| `compute_task_allocation` | 默认搜索分区或显式任务槽位匹配 | 默认连通分区；显式任务使用 SciPy 线性分配 |
| `plan_path` | 一艘艇的起终姿态路径 | Dubins六族、仅前进的有界姿态格搜索 |
| `plan_search` | 舰队搜索或显式区域搜索/重搜索候选 | 连通分区、区域条带、Dubins 转场与闭合巡回 |
| `plan_tracking` | 选择 2/3 艇、观测位置及实际转场 | 有界团队枚举、几何/到达/能源评分和剩余搜索修复 |
| `evaluate_plan` | 检查候选是否仍可执行、是否需审批 | 能源、载荷、艇代次、相关区域签名、几何与授权 |
| `submit_mission_plan` | 唯一常规执行入口 | 不可变计划、幂等命令、权限门 |
| `get_action_status` | 查询候选、计划或决策作业 | 实际状态，不把接受当作完成 |

Extension 注册位于 `agent/extension.ts`，每个任务工具有独立参数 schema。SDK 白名单为这十个工具加受限 `read`；没有 shell、写文件、任意文件或任意网络工具。任务工具经内部 HTTP 调用 Python，请求绑定运行中的 `run_id` 和 `episode_id`；取消或租约过期后拒绝迟到执行。

算法标识：`connected_partition`、`dubins_hybrid`、`strip_coverage`、`slot_assignment`、`distance_band`，只能用于对应工具；`default` 选择默认算法。替换算法须保持单位、失败语义和副作用边界，计算函数不能直接操纵仿真器。

省略 `members` 的舰队搜索当前使用整张任务地图；指定搜索 bbox 时必须同时提供明确成员，否则返回 `bbox_requires_explicit_members`，不会静默扩大到全域。显式区域不能占用其他艇的责任格，空区域或扣除已有归属后不连通的区域被拒绝。待批候选不改变当前任务；提交及批准时复核艇代次、成员归属和受影响区域签名，无关区域变化不会仅因全局版本增加而令审批失效。

`plan_path` 是几何实验工具，不能单独提交执行：前向恒速艇到达普通路径末端不能直接停车。可执行搜索使用闭合路径；跟踪失效且没有已授权续行动作时保护性暂停。

## Skill 与权限

Skill 位于 `agent/skills/multi-uuv-recon-tracking/SKILL.md`。Worker 使用 SDK 资源加载器指定这份受信 Skill，关闭其他自动发现；正文通过受限 `read` 实际读取，五份 `references/` 文档按需读取。白名单包含搜索、跟踪、能源轮换、审批和工具契约参考，拒绝越界路径和符号链接替换。资源发现与已执行读取是两回事。

权限规则由 Python 执行：Request 对新计划要求审批，已批准常驻规则内的动作继续；Assisted 按任务类型、剩余能源和接触不确定性计算启发式风险，超过 0.55 时审批；Full 不逐项审批，但不能跳过硬检查。当前基准分为搜索 0.2、跟踪/重搜索 0.6，再叠加能源与不确定性项，不是固定工具分数，也不是事故概率。

审批显示搜索区及单独的 `execution_domain`。后者包含完整转场路径包络，通常大于搜索 bbox；跟踪授权域是整张地图。活动控制始终检查批准的域。审批窗口为600仿真秒；已激活的计划持续有效，直到被替换、停止或安全检查失败。搜索循环属于原计划，不需要每圈重新批准。

## 观测、能源与接替

主动观测提供带噪距离和方位，被动观测只提供带噪方位。集中式恒速扩展卡尔曼滤波器（EKF）估计 `[x,y,vx,vy]` 及协方差。新建跟踪队先以主动模式执行转场与捕获；至少两艇实际入位、取得当前有效观测且几何与不确定性达标后，团队切换被动模式。只有随后连续3秒的真实团队被动观测满足条件，才累计协同跟踪时间。已有被动团队的接替艇维持被动模式。主动捕获、主动重搜索均不算连续被动跟踪；界面遥测显示实际传感器模式。

覆盖账本按全局栅格保存有效主动扫描时间，不因换艇或重新编号清零。覆盖率分母与分区采用同一完整栅格障碍检查，排除与障碍及其 8 m 余量相交的格子；默认场景为 1584 个可扫描格，不是固定 1600 格。成功的舰队分配保持 `K=搜索艇数`；跟踪转场、跟踪和退出艇不算搜索艇。连通区域和路径可行不代表已经扫描完成。

任务指标中的未扫描积压为可扫描格减去曾扫描格；近30分钟覆盖率以全部可扫描格为分母，30分钟重访及时率以曾扫描格为分母，尚未扫描时显示“无数据”。接替成功率为实际完成次数除以实际发起次数，进行中的接替也计入分母；未发起接替时无成功率。发起次数随检查点保存；旧检查点仅在完整事件历史可证明分母时回填，历史截断时保持未知，不把未知显示成0。

剩余航程按实际移动扣减。获授权的低能量艇沿可行退出路线越过大任务区边界后，同一更新补入满能量新代次；新入口检查其他艇及已预留的同时补入位置。旧代次审批和计划失效，轨迹不连接新旧实体。无安全入口或覆盖修复失败时保护性暂停，不先删艇。

自动接替目前是有界的二艇团队策略：增加第三艇转场，连续获取有效被动观测后才释放旧艇。已有三艇团队不加入第四艇，而由能源阈值退出并报告退化；尚未实现任意三艇团队的无间断接替保证。

## PI 会话与 LongCat 配置

Worker 订阅原生消息、工具、压缩、重试和队列事件，按 settled/idle 语义结束决策作业，不把每个 `agent_end` 当作所有后续输入已处理。更换 episode 会重新创建并订阅会话；Python 检查点独立于 PI 对话记忆。

反馈经原生队列接受并 ACK 后仍持久保留，直到 worker 在会话 settled 后报告完成。回合失败或租约过期会重新排队尚未确认完成的反馈，恢复后可能重复投递；每条反馈最多尝试三个恢复回合，耗尽后原消息明确标记失败，不无限重试。重试保留原消息身份，较早反馈仍排在较新待处理输入之前。同一 `command_id` 的任务提交仍使用幂等回执，但这不等于所有模型决策恰好执行一次。每个运行回合的待送达与已接受反馈合计最多 20 条；人工取消清除该回合的反馈。

- 兼容接口：`https://api.longcat.chat/openai/v1`。
- 默认模型：`LongCat-2.0`，可通过 `LONGCAT_MODEL` 显式覆盖。
- `openai-completions` 工具协议，关闭 thinking，输出上限4096 tokens。
- 单回合最多 24 次任务工具调用、12000 个公开会话事件，180 秒墙钟截止；成功回合后的15秒冷却仅限制普通巡检，人工消息和发现目标、目标丢失、能源退出事件可绕过冷却。失败重试等待5秒。受限 Skill 读取不计入任务工具调用计数。
- 工作租约15秒，每3秒心跳；失联作业标记失败，不盲目重放已经提交的动作。worker 离线显示使用独立的30秒静默阈值，容纳成功后的15秒冷却，但不延长活动回合的工具授权。
- 周期复查每30仿真秒，最多12个排队/运行作业。人工/反馈优先，其次关键任务事件，再次普通巡检；背景消息仅在同类中合并并记录最新内容。运行中的模型回合不被新事件抢占，模型响应仍有实际延迟；拥塞不会终止仿真。

官方接口与工具说明：[API 文档](https://longcat.chat/platform/docs/zh/api-docs)、[工具调用](https://longcat.chat/platform/docs/zh/tools-overview)。SDK中的费用系数暂设0，仅用于关闭不可靠估算，不代表模型免费；实际费用以服务平台账单为准。


## 边界与维护

这是游戏演示，不是水动力仿真或真实装备控制系统。默认 4 km 地图、4 m/s 前向巡航、60 m 最小半径，采用简化噪声观测和恒速 EKF，不是完整声学模型或复杂多目标关联器。没有训练 RL、完整 MPC 或复杂编队 MILP。源码和 [algorithm-report.md](algorithm-report.md) 明确方法边界；出处保留在 [DESIGN.md](DESIGN.md#15-文献依据与工程边界)。

逐艇 Dubins 路径不等于全局无冲突调度。运行时对多艇短时曲率候选进行有界联合选择，仍在长场景调试；不可行时暂停，不承诺任意场景永不暂停或始终跟踪成功。正常状态、模型工具和回放使用观测与估计；真值只用于观测生成及独立保护检查，不参与跟踪或逃逸控制转向。

内存保留最近 100 个候选、100 个作业/消息、500 条观测、5000 条事件及 32 个结束计划；待审批最多 32 个。回放每局最多 7200 帧、最多 8 局，每帧附带当时最近 30 条消息，使用 zlib 压缩写入 SQLite；可读取旧 JSON 文本帧。这不是完整对话档案，也不是跨帧消息去重存储。历史计划、幂等回执和 PI 会话另有磁盘档案，长期部署仍需备份、磁盘监控和维护。

服务仅监听本机回环地址，使用浏览器HttpOnly cookie和独立worker令牌隔离操作入口。这不是公网多用户认证系统，不应直接暴露到外网。
