# UUV-display-ui 用户手册与接口说明

版本：0.1.0  
更新时间：2026-09-23  
项目路径：`UUV-display-ui`

## 1. 项目简介

`UUV-display-ui` 是一个独立的多 UUV 实时态势显示前端，使用 React 和 Vite 开发。

前端主要负责：

- 显示任务区域、网格、UUV、目标、搜索区、跟踪区和轨迹；
- 通过 WebSocket 接收后端连续发送的任务帧；
- 根据后端 `uavs[]` 更新 UUV 位置、任务状态和轨迹；
- 根据 `info_matrix` 更新地图信息态势颜色；
- 显示观测接触、任务事件、覆盖率和模型决策结果；
- 提供仿真控制、重点区、场景船舶和回放等操作入口；
- 为算法、PI Agent、任务装配和 Skill 服务保留调用接口。

前端不直接实现以下后端业务：

- UUV 任务分配；
- 路径规划；
- LLM 决策；
- 油耗、补给和返航算法；
- 目标运动算法；
- 后端仿真时钟推进。

前端只负责发送命令、接收结果和可视化。

> 注意：当前独立 UI 内包含一份显示侧的信息量刷新逻辑，位置在
> `src/state/informationField.js`。它用于根据 UUV 扫描位置和仿真时间显示信息量衰减；
> `value_matrix` 仍然直接使用后端结果。

## 3. 启动前准备

### 3.1 安装 Node.js

建议使用 Node.js 18 或更高版本。检查：

```powershell
node --version
npm --version
```

### 3.2 安装前端依赖

在项目根目录执行：

```powershell
cd ".\UUV-display-ui"
npm install
```

如果项目中已经存在 `node_modules`，通常不需要重复安装。

## 4. 启动前端

### 4.1 启动开发服务器

```powershell
cd ".\UUV-display-ui"
npm run dev
```

默认地址：

```text
http://127.0.0.1:5173/
```

浏览器打开该地址即可看到界面。

### 4.2 启动生产构建预览

```powershell
npm run build
npm run preview
```

构建结果默认输出到：

```text
UUV-display-ui\dist\
```

### 4.3 修改后端端口

默认后端端口为 `8765`。如果后端使用其他端口，可以在启动前端时指定：

```powershell
$env:VITE_BACKEND_PORT="9000"
npm run dev
```

然后 Vite 会把以下请求代理到：

```text
http://127.0.0.1:9000
ws://127.0.0.1:9000
```

### 4.4 修改 WebSocket 地址

默认实时数据地址：

```text
ws://127.0.0.1:5173/ws/live
```

开发环境下，Vite 会将 `/ws/live` 代理到后端的 `ws://127.0.0.1:8765/ws/live`。

如需直接指定地址：

```powershell
$env:VITE_WS_URL="ws://127.0.0.1:8765/ws/live"
npm run dev
```

还可以分别指定两个 WebSocket 路径：

```powershell
$env:VITE_TELEMETRY_WS_PATH="/ws/live"
$env:VITE_STATE_WS_PATH="/ws/state"
npm run dev
```

## 5. 前后端连接关系

```text
浏览器
  │
  ├── HTTP http://127.0.0.1:5173/api/*
  │        │
  │        └── Vite 代理
  │                    │
  │                    └── 后端 http://127.0.0.1:8765/api/*
  │
  └── WebSocket ws://127.0.0.1:5173/ws/live
           │
           └── Vite WebSocket 代理
                       │
                       └── 后端 ws://127.0.0.1:8765/ws/live
```

如果浏览器中出现：

```text
ECONNREFUSED 127.0.0.1:8765
```

说明前端已经启动，但后端 `8765` 端口没有服务监听。此时需要先启动后端服务，或者修改
`VITE_BACKEND_PORT`。

如果出现：

```text
EADDRINUSE / 端口只允许使用一次
```

说明该端口已经被其他进程占用。可以查看端口：

```powershell
Get-NetTCPConnection -LocalPort 8765 -ErrorAction SilentlyContinue
```

也可以改用其他端口启动后端，并同步设置 `VITE_BACKEND_PORT`。

## 6. 实时 WebSocket 接口

### 6.1 接口地址

```text
WebSocket /ws/live
```

这是当前页面实时态势的主数据接口。

前端建立连接后：

1. 接收后端发送的 JSON 文本；
2. 解析为一个完整任务帧对象；
3. 读取 `frame_id`；
4. 使用 `uavs[]` 更新 UUV；
5. 使用 `info_matrix` 更新信息态势；
6. 使用 `value_matrix` 显示地图价值；
7. 根据上一帧和当前帧进行短暂位置插值；
8. 如果连接中断，自动重连。

前端会定时发送：

```text
ping
```

后端建议返回：

```text
pong
```

前端收到 `pong` 后不进行页面更新。

### 6.2 状态 WebSocket 接口

```text
WebSocket /ws/state
```

这是预留的后端状态推送接口，封装在：

```text
src/api/websocketApi.js
```

当前主页面使用的是 `/ws/live`。如果后端以后将仿真运行状态、连接状态或算法状态单独推送，
可以使用 `connectStateStream()` 接入，而不需要修改页面组件。

### 6.3 WebSocket 最小帧

后端至少应发送：

```json
{
  "frame_id": 0,
  "sim_time_min": 0,
  "timestamp": "00:00:00",
  "task_area": {
    "width_km": 100,
    "height_km": 100,
    "cell_size_km": 5
  },
  "uavs": []
}
```

实际项目建议发送原项目兼容的完整 `mission-frame/v2` 数据。

### 6.4 主要帧字段

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `frame_id` | number | 帧编号，连续仿真时应不断增加 |
| `episode_id` | string | 当前仿真任务编号 |
| `sim_time_min` | number | 仿真时间，单位为分钟 |
| `timestamp` | string | 页面显示时间 |
| `cycle` | number | 决策周期编号 |
| `runtime_status` | string | 仿真运行状态 |
| `task_area` | object | 任务区域尺寸和栅格大小 |
| `info_matrix` | number[][] | 信息量矩阵，值通常为 0 到 1 |
| `value_matrix` | number[][] | 区域价值矩阵，值通常为 0 到 1 |
| `uavs` | object[] | UUV 列表 |
| `trail` | array[] | 单个 UUV 的历史轨迹 |
| `search_regions` | object[] | 搜索区域 |
| `track_regions` | object[] | 跟踪区域 |
| `contacts` | object[] | 观测接触或目标 |
| `obstacles` | object[] | 雷暴等障碍区域 |
| `events` | object[] | 事件日志 |
| `coverage_metrics` | object | 持续搜索覆盖率 |
| `scenario_vessels` | object[] | 场景中的目标船舶 |

### 6.5 `uavs[]` 字段说明

示例：

```json
{
  "id": "UAV-1",
  "position": [4.5, 7.5],
  "trail": [
    [3.5, 7.5],
    [4.0, 7.5],
    [4.5, 7.5]
  ],
  "status": "searching",
  "operation_mode": "coverage",
  "operational_status": "available",
  "assigned_region_id": "SEARCH-1",
  "target_group_id": null,
  "control_owner": "system",
  "task_visual": {
    "task_type": "coverage",
    "phase": "scanning",
    "route_source": "allocator",
    "route_status": "active"
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `id` | UUV 标识。界面会把 `UAV-1` 显示为 `UUV-1` |
| `position` | 当前栅格坐标，格式为 `[列, 行]` |
| `trail` | 历史轨迹点数组，格式为多个 `[列, 行]` |
| `status` | 当前运行状态 |
| `operation_mode` | 任务运行模式 |
| `operational_status` | 是否故障、可用等运行属性 |
| `assigned_region_id` | 分配的搜索区或跟踪区编号 |
| `target_group_id` | 当前跟踪目标组编号 |
| `control_owner` | 当前控制权来源 |
| `task_visual` | 任务显示信息和内部任务阶段 |

### 6.6 UUV 任务模式

当前界面支持以下任务模式：

| 值 | 中文 |
| --- | --- |
| `idle` | 待命 |
| `coverage` | 区域搜索 |
| `probe` | 目标侦察 |
| `track` | 协同跟踪 |
| `return` | 返航 |
| `holding` | 等待降落 |

运行状态和任务模式需要区分：

| 运行状态 | 中文 |
| --- | --- |
| `idle` | 待命 |
| `transit` | 转场 |
| `searching` | 搜索扫描 |
| `tracking` | 持续跟踪 |
| `returning` | 返航 |
| `holding` | 等待降落 |
| `failed` | 故障停用 |

## 7. 信息量刷新和衰减机制

### 7.1 代码位置

```text
src/state/informationField.js
```

入口在：

```text
src/hooks/useWebSocket.js
```

页面通过：

```text
src/App.jsx
```

将计算后的信息矩阵传给地图和右侧面板。

### 7.2 刷新流程

```text
收到 WebSocket 帧
  ↓
读取 frame.sim_time_min
  ↓
读取 frame.uavs[]
  ↓
判断 UUV 是否处于搜索或跟踪状态
  ↓
记录扫描网格的最近扫描时间
  ↓
按照半衰期重新计算 info_matrix
  ↓
地图颜色、统计面板、鼠标悬停共同刷新
```

### 7.3 当前默认参数

| 参数 | 当前值 |
| --- | --- |
| 扫描半径 `R` | 2 个栅格 |
| 搜索半衰期 | 30 分钟 |
| 跟踪半衰期 | 15 分钟 |

计算公式：

```javascript
info = Math.exp(-Math.log(2) * age / halfLife);
```

也就是说：

- 刚被扫描的网格，信息量接近 `1.0`；
- 搜索状态下经过 30 分钟，信息量约为 `0.5`；
- 跟踪状态下经过 15 分钟，信息量约为 `0.5`；
- 后续继续按指数规律衰减。

### 7.4 扫描范围

如果后端提供：

```text
uav.sar_footprint
```

前端优先使用该字段标记扫描网格。

如果后端没有该字段，前端使用以 UUV 为圆心、半径
`R=2` 个栅格的圆形范围，并补充位置移动经过的网格。

### 7.5 后端矩阵和前端显示矩阵

前端保存两份概念上的矩阵：

- 后端矩阵：`backend_info_matrix`，用于记录后端发送的原始结果；
- 当前显示矩阵：`info_matrix`，用于地图显示和本地衰减计算。

首次连接或前端模型初始化时，后端 `info_matrix` 会被用于建立初始信息场。之后页面根据
UUV 扫描位置和 `sim_time_min` 继续计算显示矩阵。

`value_matrix` 不在前端重复计算，页面直接使用后端发送的结果。

## 8. HTTP 接口总览

所有 HTTP 请求默认使用相对路径，例如：

```text
/api/state
```

开发服务器会将其代理到后端 `http://127.0.0.1:8765`。

### 8.1 通用接口

封装文件：

```text
src/api/httpApi.js
```

支持：

| 方法 | 用途 |
| --- | --- |
| `httpApi.get(path, options)` | GET |
| `httpApi.post(path, payload, options)` | POST JSON |
| `httpApi.put(path, payload, options)` | PUT JSON |
| `httpApi.patch(path, payload, options)` | PATCH JSON |
| `httpApi.delete(path, options)` | DELETE |
| `httpApi.getConfig()` | 获取配置 |
| `httpApi.getHealth()` | 健康检查 |

请求默认使用 JSON，默认超时时间为 10 秒。

### 8.2 健康检查和配置

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/health` | 后端健康检查 |

PowerShell 示例：

```powershell
Invoke-RestMethod "http://127.0.0.1:8765/api/health"
Invoke-RestMethod "http://127.0.0.1:8765/api/config"
```

### 8.3 仿真状态和控制

封装文件：

```text
src/api/stateApi.js
```

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/state` | 获取当前全部仿真状态 |
| POST | `/api/simulation/start` | 启动仿真 |
| POST | `/api/simulation/pause` | 暂停仿真 |
| POST | `/api/simulation/reset` | 重置仿真 |

示例：

```javascript
import { stateApi } from "./src/api";

const state = await stateApi.getState();
await stateApi.startSimulation({ episode_id: "demo-1" });
await stateApi.pauseSimulation({ episode_id: "demo-1" });
await stateApi.resetSimulation({ episode_id: "demo-1" });
```

请求体由后端合同决定。前端只透传 JSON，不在 UI 内修改仿真算法参数。


## 12. 后端联调检查清单

### 前端检查

1. `npm run dev` 能正常启动；
2. 浏览器能够打开 `http://127.0.0.1:5173/`；
3. 页面顶部连接状态不是“连接中”或“重连中”；
4. 浏览器开发者工具 Network 中能看到 `/ws/live`；
5. 地图能够显示后端发送的第一帧；
6. `frame_id` 会随着后端帧增加；
7. UUV 的 `position` 会变化；
8. `trail` 点数会增加或保持后端最新结果；
9. `info_matrix` 能改变地图颜色；
10. UUV 任务状态和运行状态能显示。

### 后端检查

1. `8765` 端口确实有服务监听；
2. `/api/health` 能返回 200；
3. `/ws/live` 能接受 WebSocket 连接；
4. WebSocket 发送的是合法 JSON；
5. 每帧包含递增的 `frame_id`；
6. `uavs[]` 中包含 `id` 和 `position`；
7. `task_area` 的单位和栅格尺寸正确；
8. `sim_time_min` 会随仿真推进；
9. 后端关闭时，前端能显示断开并自动重连；
10. 不要把燃料、油耗或补给字段作为 UI 正常运行的必要条件。
